# Выделенный Edge и управление агентом

Этот раздел нужен, когда владелец хочет работать в основном браузере параллельно с агентом. Используй собственный постоянный каталог данных для отдельного Edge. Переход между видимым и фоновым режимом выполняется с одним и тем же каталогом, чтобы сайт мог сохранить авторизацию и результат ручной проверки.

## Определение браузера и портов

Найди установленный `msedge.exe` через стандартную запись App Paths или существующую установку Microsoft Edge. Проверь путь и подпись Microsoft. Выбери свободный TCP-порт управления, например первый свободный из диапазона 19000–19100. Порт локального прокси берётся из `routing-settings.json`. Оба порта имеют разные назначения.

```powershell
$routing = Get-Content -LiteralPath $settings -Raw | ConvertFrom-Json
$proxyPort = [int]$routing.proxy_port
$edgeRoot = Join-Path $runtime 'edge-agent'
$edgeData = Join-Path $edgeRoot 'browser-data'
$ports = @(Get-NetTCPConnection -State Listen | Select-Object -ExpandProperty LocalPort -Unique)
$debugPort = 19000..19100 | Where-Object {$_ -notin $ports} | Select-Object -First 1
if (!$debugPort) { throw 'Не найден свободный порт управления браузером' }
New-Item -ItemType Directory -Path $edgeData -Force | Out-Null
```

Значение `$edgeExe` в следующих командах — найденный и проверенный бинарный файл. `$edgeData` относится только к выделенному экземпляру агента. Первый запуск этого профиля создаёт новую браузерную сессию. При необходимости владелец входит на сайты в видимом окне. Экспортировать куки или переносить личный профиль для этого не требуется.

## Первый запуск для входа

Сначала проверь слушатель Mihomo. Затем создай аргументы запуска и открой видимый Edge.

```powershell
$browserArgs = @(
    '--remote-debugging-address=127.0.0.1',
    ('--remote-debugging-port='+$debugPort),
    ('--user-data-dir="'+$edgeData+'"'),
    ('--proxy-server=http://127.0.0.1:'+$proxyPort),
    '--no-first-run',
    '--no-default-browser-check',
    'https://www.avito.ru/profile'
)
Start-Process -FilePath $edgeExe -ArgumentList $browserArgs -WindowStyle Normal
```

Не добавляй `--no-proxy-server` или исключение `*.ru` в команду браузера. Прямой выбор российских сайтов происходит внутри Mihomo. При исключении на уровне браузера исходящий запрос подчиняется маршрутам Windows, которые может перехватить VPN.

Проверь через `Get-NetTCPConnection`, что порт `$debugPort` слушается на `127.0.0.1` или `::1` и принадлежит процессу с точными `ExecutablePath`, каталогом `$edgeData` и аргументом порта. Потом обращайся к `/json/version`. Публикация отладочного порта в LAN для этой схемы не требуется.

Авито может запросить вход или ручную проверку. Владелец проходит её сам в данном окне. Затем проверь, что открылся кабинет. Переход между вкладками в видимом окне может требовать фокуса, поэтому полноценную параллельную работу агента начинай после перехода в headless.

## Возврат того же профиля в фон

Дождись завершения текущих задач, использующих именно выделенный Edge. При наличии настроенной задачи восстановления браузера временно отключи её триггер и останови только её супервизор, чтобы он не запустил прежний режим посередине переключения.

Установи, что обнаружен ровно один корневой процесс нужного Edge и его loopback-порт. Закрой этот браузер штатной CDP-командой `Browser.close`. Она завершает весь выделенный экземпляр, поэтому до её отправки проверь собственность порта и каталога данных. Такой способ даёт браузеру сохранить состояние перед выходом.

Пример отправки после проверки владельца порта следующий.

```powershell
$versionUri = 'http://127.0.0.1:'+$debugPort+'/json/version'
$info = Invoke-RestMethod -Uri $versionUri -NoProxy -TimeoutSec 3
$uri = [Uri]$info.webSocketDebuggerUrl
if ($uri.Scheme -ne 'ws' -or $uri.Host -ne '127.0.0.1' -or $uri.Port -ne $debugPort -or
    $uri.AbsolutePath -notlike '/devtools/browser/*') { throw 'Неожиданный адрес управления' }
$socket = [Net.WebSockets.ClientWebSocket]::new()
$cancel = [Threading.CancellationTokenSource]::new(5000)
try {
    $socket.ConnectAsync($uri,$cancel.Token).GetAwaiter().GetResult()
    $message = [Text.Encoding]::UTF8.GetBytes('{"id":1,"method":"Browser.close"}')
    $socket.SendAsync([ArraySegment[byte]]::new($message),[Net.WebSockets.WebSocketMessageType]::Text,$true,$cancel.Token).GetAwaiter().GetResult()
} finally {
    $socket.Dispose()
    $cancel.Dispose()
}
```

Дождись выхода точного корневого процесса и освобождения порта. Если это не произошло, диагностируй оставшийся процесс и активную задачу. Массовое завершение всех `msedge.exe` затронет обычный браузер владельца.

Запусти тот же профиль с добавленным `--headless=new`. Порт управления и адрес локального прокси должны сохраниться.

```powershell
$backgroundArgs = @('--headless=new') + @(
    '--remote-debugging-address=127.0.0.1',
    ('--remote-debugging-port='+$debugPort),
    ('--user-data-dir="'+$edgeData+'"'),
    ('--proxy-server=http://127.0.0.1:'+$proxyPort),
    '--no-first-run',
    '--no-default-browser-check',
    'about:blank'
)
Start-Process -FilePath $edgeExe -ArgumentList $backgroundArgs -WindowStyle Hidden
```

Подтверди аргумент `--headless`, владельца порта и ответ `/json/version`. Результат ручной проверки сайта может иметь ограниченный срок действия, поэтому доступ к кабинету проверяется ещё раз после переключения.

## Привязка к Hermes

Сначала обнаружь фактически установленный Hermes, его версию, активный профиль и доступные инструменты. Используй текущую документацию этой версии. При наличии `browser.cdp_url` добавь адрес выделенного браузера в существующий раздел `browser`, сохранив остальные настройки. Ниже фрагмент, который агент подставляет с выбранным портом.

```yaml
browser:
  cdp_url: "http://127.0.0.1:REPLACE_WITH_LOCAL_DEBUG_PORT"
  use_real_profile: false
  headed: false
```

Это фрагмент для объединения с конфигурацией выбранного профиля. Поля, отсутствующие в схеме установленной версии, уточни по её документации или исходникам. В некоторых версиях `browser_exec` является единственным браузерным инструментом и устаревший `browser.backend` удаляется миграцией. Отключённое `use_real_profile` означает использование созданного для агента каталога, а не чтение личного профиля.

Если `browser_exec` отсутствует, проверь установку браузерных зависимостей и набор инструментов этого профиля. Подключение к существующему личному профилю имеет отдельный механизм согласия. Для выделенного профиля с уже разрешённым локальным CDP используй предусмотренную этой версией привязку. [Документация Hermes](https://hermes-agent.nousresearch.com/docs/)

MCP-коннектор и туннель Hermes настраиваются получателем на его аккаунте. Этот архив описывает браузерный маршрут поверх существующего подключения. Публичного универсального ключа туннеля или готовой чужой сессии не существует. Если туннель уже настроен, оставь его учётные данные локальными.

### Проверка без фокуса

Для каждой диагностики создай новую именованную сессию браузерного инструмента и собственную вкладку. Сначала проверь `about:blank`, затем — нужный сайт. Пример для версий с такими помощниками `browser_exec` следующий.

```python
probe = "about:blank#agent-background-check"
target = cdp("Target.createTarget", url="about:blank")["targetId"]
try:
    switch_tab(target)
    goto_url(probe)
    wait_for_load()
    assert js("[location.href, document.readyState]") == [probe, "complete"]
    print("BACKGROUND_BROWSER_OK")
finally:
    current = cdp("Target.getTargetInfo", targetId=target)["targetInfo"]
    if current["url"] in ("about:blank", probe):
        print("probe_closed=" + str(cdp("Target.closeTarget", targetId=target)["success"]))
```

Следующая задача должна открыть `https://www.avito.ru/profile`, перейти в «Мои объявления» штатной ссылкой и подтвердить список, фильтры или пустое состояние. Сохрани `targetId` и закрой только созданную вкладку. Данные объявлений, контакты и сообщения для проверки доступа не нужны.

Если задача отправлена через Hermes MCP, сохрани её `task_id` и опрашивай состояние до завершения. Статусы `ready`, `queued` и `running` подтверждают разные этапы. Даже `completed` требует прочитать результат и проверить, что сайт фактически открылся.

### Ошибка Windows breakaway

В некоторых версиях Hermes новая задача использует локальный gateway. При запуске из ограниченного Windows Job создание фонового gateway может завершиться `windows_breakaway_unavailable`. Проверь штатный `hermes gateway ensure` и действующую схему мультиплексирования установленной версии.

Обычный путь восстановления — штатный `hermes gateway install` и запуск этого gateway через пользовательскую службу/задачу или его Windows Startup launcher. Выбор профиля зависит от версии и текущего владельца gateway. Отдельный gateway профиля создавай, если это требуется имеющимся мостом и допустимо текущей архитектурой. Перед `--force` проверь отсутствие другого gateway, дублирующих подключений и конфликтов одного профиля. Основной gateway, уже обслуживающий профиль, может быть достаточен. [Windows в Hermes](https://hermes-agent.nousresearch.com/docs/user-guide/windows-native)

### Автозапуск отдельного Edge

Используй стабильный локальный launcher, который читает локально созданные пути и порты, ждёт слушатель Mihomo, проверяет единственный собственный Edge и его loopback-порт, затем запускает отсутствующий браузер с `--headless=new`. Сохраняй `browser-data` на диске между запусками. Планировщик должен работать под тем пользователем Windows, чей выделенный профиль создан для агента.

Триггеры и параметры задачи берутся из примера в `setup.md`. Для браузера нужен собственный mutex и проверка пары «исполняемый файл + точный `--user-data-dir`». Порт без такого владельца считается конфликтом. При ручной авторизации launcher должен допускать видимый собственный экземпляр и не перезапускать его в headless до окончания передачи управления.

Авторизация в нужном сайте, запуск фонового браузера и связь через Hermes проверяются после реального входа в Windows. Автоматизация первоначального входа и MFA зависит от сайта и участия владельца.
