# Проверка результата

## Два независимых выхода

Проверь физический и VPN-адаптеры отдельными HTTPS-запросами, принудительно привязанными к каждому интерфейсу. Затем сравни выход внешнего запроса через локальный прокси с выходом VPN. Входящий `verify_egress.py` делает это через Windows `IP_UNICAST_IF`. Публичные адреса остаются в памяти процесса, в выводе только булевы результаты.

Нужен Python 3.11 или новее со стандартной библиотекой и доступом к HTTPS. При имеющемся Hermes можно использовать его исправный Python. Сначала проверь исполняемый файл и версию. Устанавливать ещё один Python при наличии подходящего не требуется.

```powershell
$directIndex = (Get-NetAdapter -IncludeHidden | Where-Object Name -eq $directAlias).ifIndex
$vpnIndex = (Get-NetAdapter -IncludeHidden | Where-Object Name -eq $vpnAlias).ifIndex
& $python (Join-Path $kit 'scripts/verify_egress.py') `
    --direct-index $directIndex --vpn-index $vpnIndex --proxy-port $proxyPort
```

Ожидается такой результат.

```json
{
  "direct_and_vpn_differ": true,
  "proxy_foreign_matches_vpn": true,
  "verified": true
}
```

Используется публичный сервис `api.ipify.org`, запросы передают ему обычные сетевые адреса проверяемых соединений. Этот домен должен идти через правило по умолчанию `VPN`, иначе сравнение не подтверждает нужное условие. Совпадающие прямой и VPN-адреса означают, что различие выходов не подтверждено. Ошибка запроса может означать недоступность сервиса, DNS, маршрута или TLS и требует диагностики.

## Правила российских и внешних сайтов

Сделай по одному запросу к российскому и внешнему публичному сайту через локальный HTTP-прокси. В PowerShell вызывай `curl.exe` с расширением, чтобы не попасть на старый псевдоним PowerShell. `--noproxy` с неиспользуемым тестовым именем предотвращает влияние унаследованного списка исключений на эти два запроса.

```powershell
$proxy = 'http://127.0.0.1:'+$proxyPort
& curl.exe --silent --show-error --max-time 20 --noproxy no-bypass.invalid `
    --proxy $proxy --output NUL --write-out 'direct_probe_http=%{http_code}\n' https://ya.ru/
& curl.exe --silent --show-error --max-time 20 --noproxy no-bypass.invalid `
    --proxy $proxy --output NUL --write-out 'vpn_probe_http=%{http_code}\n' https://example.com/
```

Посмотри только новые строки `core.stdout.log` и при необходимости `core.stderr.log`. Для `ya.ru:443` должно быть `using ISP_DIRECT`, для `example.com:443` — `using VPN`. При подключённом UI используй журнал соединений активного ядра. Порядок правил и значение `using` подтверждают выбранный выход. Отдельная привязка интерфейса и проверка IP подтверждают, куда этот выход ведёт.

Код 200 или редирект подтверждают HTTP-ответ. Ответ 403 или проверка сайта могут получаться при работающей сети. Сетевая ошибка, код 000, выбранный выход и ограничение сайта — разные факты. Полные журналы могут содержать посещённые домены и другие индивидуальные сведения. В отчёт вынеси только проверенные имена выходов, тестовые домены, время и результат.

## Основной браузер и Яндекс Диск

Открой российский сайт в основном браузере и сопоставь время с новой строкой журнала. Затем открой внешний сайт и сопоставь его выход. Проверь собственные прокси-расширения, аргументы запуска браузера и автоматическую конфигурацию, если журнал пуст.

В Яндекс Диске проверь режим сети и прокси, затем безопасную операцию синхронизации существующего файла без изменения данных. Если требуется запись, используй явно разрешённый владельцем тестовый файл. Наличие иконки «подключено» проверяется вместе с фактическим завершением операции. Дополнительные домены добавляй по относящимся к приложению соединениям. `yandex.ru` не охватывает `yandex.net`, `yastatic.net` или `yandex.com`.

При системном исключении `*.ru` браузер может обойти Mihomo и пойти по глобальному маршруту VPN. Поэтому российские домены задаются в правилах ядра. Список системного обхода в этом комплекте охватывает локальные назначения.

## Фоновый Edge и Hermes

Выполни последовательность из [browser-and-hermes.md](browser-and-hermes.md). Для фонового Edge обязательны тот же локальный прокси, отдельный постоянный каталог данных и доказанная связь агента с этой сессией. Для Авито открой «Мои объявления» и подтверди список, фильтры или пустое состояние раздела. Личная информация из объявлений для проверки связи не требуется.

Успех ручной проверки в видимом окне проверь ещё раз после возврата того же профиля в headless. Сайт может повторно потребовать проверку. Если это произошло, состояние маршрута всё равно оценивается по журналу и интерфейсу.

## Автозапуск

Перед настоящей перезагрузкой безопасно проверь запуск супервизора через созданную задачу. Повторный запуск задачи с уже работающим супервизором должен сохранять единственный процесс ядра и слушатель. Входящий mutex и `MultipleInstances IgnoreNew` предотвращают дубли.

```powershell
Get-ScheduledTask -TaskName $taskName | Select-Object TaskName,State
Start-ScheduledTask -TaskName $taskName
& (Join-Path $scripts 'Watch-Routing.ps1') -SettingsFile $settings -CheckOnly
```

Проверь включённое состояние задачи, триггер входа, минутный повтор, правильный аккаунт, реальный путь `pwsh.exe` и существующий каталог скриптов. Автоподключение VPN проверь в настройках его клиента.

Перезагрузку выполняет владелец или агент при наличии разрешения и после сохранения текущей работы. После входа проверь без ручного запуска компонентов следующее.

- Сначала появился физический интернет, затем VPN-адаптер.
- Ядро и супервизор запустились самостоятельно, выбранный порт принадлежит нужному процессу.
- Системный прокси сохранился, оба тестовых направления работают.
- Если настроен агентский Edge, он поднялся с нужным профилем и прокси.
- Команда через Hermes завершилась осмысленным результатом в браузере.

Измерь задержку от входа пользователя до первого подтверждённого успешного запроса. Для VPN с MFA при каждом входе зафиксируй, что дальнейшее восстановление сети зависит от этой авторизации. Проверка конфигурации задачи и проверка после фактической перезагрузки должны быть явно указаны в локальном отчёте.

## Что сохранить в локальный отчёт

Дата проверки, версия ядра и источник, выбранные локальные псевдонимы адаптеров, свободный порт, активный механизм запуска, проверенные маршруты и приложения, факт перезагрузки, оставшиеся ограничения и путь к откату. Секреты и полный публичный IP для отчёта не нужны. При передаче отчёта третьим лицам обезличь локальные пути, имена профилей и журнал посещений.
