# Раздельная маршрутизация Windows

Реализуй на компьютере владельца следующую схему. HTTP/SOCKS-приложение передаёт запрос локальному Mihomo. Правила выбирают выход через физический адаптер для российских сайтов и через адаптер существующего VPN для остальных. Названия адаптеров, порты, пути, VPN и браузерные профили определяй на целевом ПК.

В этом навыке `ISP_DIRECT` обозначает выход через провайдера, `VPN` — выход через уже подключённый VPN-адаптер. Оба выхода имеют тип `direct`, а различаются `interface-name`. Сам Mihomo принимает локальные запросы и выбирает сетевой адаптер. Это рабочая схема для VPN, который предоставляет интерфейс Windows и допускает прямое соединение через физический интерфейс.

## Как выполнять

1. Прочитай [инструкцию установки](references/setup.md) и [проверку результата](references/verification.md). Выполни обнаружение локального окружения. Сохраняй обнаруженные сведения на компьютере владельца.
2. Используй существующий подходящий VPN. При нескольких адаптерах выбери VPN по фактическим маршрутам и проверке выхода. При нехватке прав или недоступности VPN сообщи конкретную причину. Учётные данные и ручная авторизация принадлежат владельцу этого ПК.
3. Выбери одного владельца ядра. Для готового Clash Verge Rev используй раздел о локальном профиле. Для воспроизводимой настройки с существующим отдельным VPN используй входящие скрипты и отдельный Mihomo. Выбор основан на найденном окружении и цели пользователя.
4. Сгенерируй новую конфигурацию из `assets/routing-policy.json`, проверь её реальным ядром через `-t`, затем запусти. Привяжи каждый выход к нужному адаптеру. Включи системный прокси после проверки локального слушателя.
5. Проверь разные классы сайтов, приложение с собственным прокси и фоновый браузер, если он нужен. Подтверди фактический выход по журналу ядра и проверке интерфейсов. Доступность локального порта подтверждает только работу слушателя.
6. Настрой запуск после входа в Windows и выполни проверки из раздела о перезагрузке. При работе через Hermes дождись результата конкретного задания и оцени его содержание.
7. Оставь владельцу краткую инструкцию эксплуатации из [setup.md](references/setup.md#эксплуатация), локальный отчёт и путь к резервной копии. Возврат к прежнему состоянию описан в [диагностике и откате](references/troubleshooting.md).

Дополнительные сведения о выделенном Edge и Hermes находятся в [browser-and-hermes.md](references/browser-and-hermes.md). Читай этот файл при настройке фонового доступа. Источники и границы проверенной схемы находятся в [sources.md](references/sources.md).

## Решения без лишних уточнений

Выбирай свободный порт из диапазона 7897–7997. Предлагай физический адаптер по активному шлюзу и метрике. Подтверждай VPN по маршрутам и фактическому выходу. Сохраняй существующий способ входа пользователя в VPN. Если он уже настроен, повторная выдача ключей не нужна. Используй пути относительно `$env:LOCALAPPDATA` и `$PSScriptRoot`.

Шаблоны содержат публичные домены и обозначения адаптеров. Конфигурацию на целевом ПК создавай заново. При распространении архива включай исходные шаблоны, инструкции и скрипты. Обнаруженные адреса, токены, подписки, куки, журналы, профиль браузера и созданные локальные конфигурации хранятся отдельно.

Ручная проверка сайта, пароль, MFA и согласие ОС могут требовать участия владельца. Выполни всю независимую подготовку и предъяви конкретное оставшееся действие. Успех раздельной маршрутизации и успех входа на сайт подтверждаются отдельно.

## Приёмка

Заверши настройку, когда российский тестовый домен использует `ISP_DIRECT`, внешний домен использует `VPN`, оба выхода проверены, браузер и нужное приложение используют локальный прокси, а автозапуск проверен. Если перезагрузка ещё не выполнена, укажи это. Зафиксируй несовместимость VPN, если его фильтр блокирует прямой выход даже при явной привязке к физическому адаптеру.
